# 潮屿 Tidehaven

一块能玩的 TBC 链游切片。玩法参考海上浮岛经营：从木筏出发，拾荒、挨着旧建筑往外盖、让收集器和切鱼台自己生产、用鱼获和淡水养活岛民。名字、画面和数值都是原作，不包含参考对象里的英雄、联盟或城战。

## 怎么玩

在 `tidehaven/` 目录启动静态页：

```bash
npm test
npm start
```

浏览器打开 `http://127.0.0.1:4173`。

本地循环不需要钱包：

1. 点「收集器」，再点木筏旁边的海面。
2. 「出海拾荒」捞木板、金属、塑料、绳索，有时是鱼和淡水。鲨鱼会让这一网落空。
3. 盖切鱼台和海水提取，否则岛民吃光库存后生产会停。
4. 「快进 20 秒」用来看生产和开伙，不必干等。

存档在浏览器 `localStorage`（`tidehaven.v1`）。离线最多结算 2 小时。

## 什么上链

TBC 的 FT 在 `FT_MINT` 时一次铸完供应量，之后不能按每一网拾荒再增发。所以节拍留在本地，链上只做三件玩家钱包签得了名的事：

| 动作 | 钱包调用 | 含义 |
| --- | --- | --- |
| 发行四种物资 | `FT_MINT` | 木板、金属、塑料、绳索各 100 万，小数位 0。返回 txid 的第一段是合约号 |
| 创建浮岛合集 / 铸造快照 | `COLLECTION_CREATE`、`NFT_CREATE` | 快照写进 NFT 的 `attributes`，不能回改。要更新就再铸一枚 |
| 建造时转出花费 | `FT_TRANSFER` | 勾选后，把本次木板、金属、塑料、绳索花费转到金库地址 |
| 签署存档 | `signMessage` | 对规范 JSON 签名，当检查点 |

没有注入 `Turing` 时，这些按钮走演练：交易参数按 [Turing Wallet sendTransaction](https://docs.turingwallet.xyz/en/api/sendTransaction) 组好，但不广播。装上钱包后，同一按钮调用 `Turing.sendTransaction([param])`；一次要发多笔时用 `sendBatchRequest`。

鱼获和淡水只在本地消耗，不发行成 FT。拾荒奖励也先留在本地。若要让奖励真的到账，需要一个金库地址把已铸造的 FT 转给玩家，那个私钥不能放在网页里。

链上转账失败时，这次建造会取消，本地材料退回。

## 目录

- `src/rules.js`：拾荒、建造、生产、开伙。纯函数。
- `src/chain.js`：FT / NFT / 签名消息的参数。
- `src/main.js`：页面和钱包适配。
- `test/`：`node --test`。
